# Безопасность (SECURITY)

## Tauri 2

- CSP: `default-src 'self'`, скрипты только свои, `style-src 'self' 'unsafe-inline'` (нужен
  Tailwind и инлайн-стилям анимаций), `img-src 'self' data:`. Внешние домены не разрешены —
  сеть работает только из Rust.
- Capabilities: минимальный набор. Из плагинов подключены `dialog` и `notification`;
  `fs`, `shell`, `http` не выдаются. Весь доступ к файлам и процессам — через собственные
  команды с валидацией.
- Frontend не может передать произвольную команду: все входы валидируются в Rust,
  внешние процессы запускаются именованными сценариями с проверенными аргументами.

## Валидация на границе Rust

- Все пути от UI проверяются: резолв в канонический путь, проверка, что он находится внутри
  разрешённого корня (`controlDir` / `%APPDATA%\control` / папка версии), запрет `..`.
- Имена версий, стратегий и файлов — без путей и разделителей, только допустимые символы.
- Данные GitHub и имена стратегий выводятся через React (авто-экранирование).
  `dangerouslySetInnerHTML` используется в одном месте — `shared/ui/Icon`, и только для
  статических SVG-тел иконок Solar, вшитых в бандл при сборке. Пользовательские данные туда
  не попадают.

## Процессы

- Не запускать всё приложение как admin: повышение прав выполняется отдельным elevated-помощником
  и только для конкретной операции (служба, драйвер WinDivert, запись в System32). См. ADR-0001.
- Убийство процессов только по конкретному PID/дереву процессов, не по имени `winws.exe`.
- Эксклюзивность: один собственный winws; перед стартом — корректная остановка собственного
  предыдущего экземпляра; внешний экземпляр не убивается, а определяется и блокирует управление.

## Скачивание

- Только https, редиректы ограничены (≤10), размер ограничен, скачивание во временный файл.
- Проверка целостности: sha256, если релиз публикует чек-сумму; её отсутствие — предупреждение
  в интерфейсе, а не молчание. Полная подпись в источнике недоступна.
- Установка только после успешной распаковки и валидации структуры (наличие `bin/winws.exe`).

## Логи и секреты

- Логи не содержат содержимого пользовательских файлов, токенов, полных внешних URL с параметрами.
- Диагностический отчёт перед копированием проходит sanitize (whitelist-поля).

## Что проверяется перед релизом

- Аудит capabilities и CSP в `tauri.conf.json`, проверка IPC-поверхности (нет инъекций
  в аргументы процессов), тесты path traversal, проверка экранирования данных релиза,
  обновление зависимостей (`cargo audit`, `npm audit`).
