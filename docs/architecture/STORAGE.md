# Хранение данных (STORAGE)

## Принцип совместимости

Все данные остаются в `%APPDATA%\control` (и пользовательский `controlDir` для версий) —
**те же пути, что в Control 1.0.1**. Tauri-версия читает и пишет существующие файлы напрямую.
Миграции меняют только содержимое/схему, не расположение.

| Ресурс | Путь | Формат 1.0.1 | Действия |
|---|---|---|---|
| Настройки | `%APPDATA%\control\settings.json` | плоский JSON | читать как есть; при записи — атомарно + backup |
| Конфиг Zapret | `%APPDATA%\control\flowseal-config.json` | JSON (strategy, фильтры) | то же |
| Версии | `zapret-versions\vX.Y.Z\` | каталоги | без изменений; только безопасная установка/удаление |
| Временные загрузки | `temp-downloads\` | архивы | очистка при старте, если незавершённые |
| Списки | `<version>\lists\*-user.txt` | текст | только атомарная запись |
| Флаг-файлы | `<version>\utils\*.enabled` | маркеры | как в 1.0.1 |
| ACTIVE fakes | `<version>\bin\ACTIVE_*.bin` | бинарные | атомарная запись (temp+rename) |

## Атомарная запись (`storage::atomic`)

1. Сериализация + валидация (serde-схема) **до** касания файлов.
2. Запись во временный файл `*.tmp-<uuid>` **на том же томе**.
3. `sync_all()` файла.
4. (Для критичных) backup прежней версии: `settings.json.bak` — сохраняем существующий паттерн 1.0.1,
   плюс ротация до N=3 копий (`*.bak.1..3`).
5. `std::fs::rename` (атомарен на NTFS для существующего целевого). Если rename невозможен
   (лок-антивирусом) — до 3 повторов с бэкоффом, затем понятная ошибка; целевой файл не тронут.
6. Повторное чтение + проверка схемы после записи.
7. Очистка tmp в конце и при следующем старте (orphan tmp).

Никогда: усечение целевого до записи, удаление целевого заранее, «успех» без проверки.

## Блокировки и конкурентность

- `state/AppState` держит per-resource `tokio::sync::Mutex`-реестр (settings, flowseal-config,
  каждая версия, каждый список). Запись без захвата ресурса невозможна.
- Read-Modify-Write: перед записью перечитывается текущий файл; если mtime/содержимое изменилось
  с момента чтения пользователем — конфликт возвращает ошибку `CONFLICT`, UI предлагает перечитать
  или перезаписать явно. (Простая версия: перечитывать перед записью и мерджить; перезапись
  «вслепую» запрещена.)

## Повреждённые файлы

- settings/flowseal-config: если JSON не читается — сохранить копию в
  `%APPDATA%\control\corrupt\<name>.<timestamp>.json` (не удалять!), попытаться восстановить
  из `.bak`, в крайнем случае стартовать с дефолтами и показать пользователю понятное сообщение.
- Пользовательские списки: повреждение не лечится автоматически; работать не начинаем, показываем
  ошибку и путь.

## Миграция с 1.0.1

Специальной миграции схемы не требуется (форматы те же). Первая загрузка Tauri-версии:
1. Проверка существования settings.json; при наличии — чтение как есть.
2. Неизвестные ключи сохраняются (round-trip сохранение), а не выбрасываются.
3. Проблемные значения приводятся к валидным с записью предупреждения в лог и UI.

## Backup/restore приложения

Формат экспорта сохраняется совместимым с 1.0.1 (JSON-бандл: settings + flowsealConfig + userLists),
чтобы экспорты были взаимно переносимы. Restore — транзакционно: распаковка в temp, валидация,
backup текущих, замена атомарно, откат при ошибке.
