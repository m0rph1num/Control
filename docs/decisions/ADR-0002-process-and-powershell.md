# ADR-0002: Процессный слой, PowerShell и кодировки

Статус: принято.

## Решения

1. **Tokio + `tokio::process::Command`** для всех внешних процессов. Блокирующие системные
   вызовы (синхронные ожидания, тяжёлое файловое I/O) — только через `spawn_blocking`.
2. **Чтение stdout/stderr — отдельные задачи**, объединение в общий поток событий операции
   с батчингом (не чаще ~4 событий/с, хвост ≤200 строк). Никакого polling.
3. **Кодировка**: при запуске PowerShell нашими сценариями в начало команды добавляется
   установленный пролог `[Console]::OutputEncoding = [Text.Encoding]::UTF8`, и мы ожидаем UTF-8.
   Для сторонних процессов (winws, sc, ping) выходной байтовый поток конвертируется:
   попытка UTF-8 → при ошибках — cp866 (консольная кодировка RU-Windows) → `from_utf8_lossy`.
   Реализация в `process_runner::decode_output`, покрыта unit-тестами на фиксированных байтах.
4. **Никакой конкатенации команд из строк UI**: PowerShell-сценарии — константы в коде;
   пользовательские данные передаются как аргументы (`-Command` со строго сформированным
   скриптом из валидированных полей) или через параметры процесса. Все аргументы процессов —
   через массив аргументов ОС, не через строку shell.
5. **Убийство дерева**: собственные long-running процессы (winws) держатся в Job Object
   (windows-rs) с kill-on-close — падение Control не оставляет сирот, отмена убивает дерево
   детерминированно. Для разовых команд — `taskkill /PID <pid> /T /F` по конкретному PID.
6. **Таймауты** — параметр каждого запуска; по таймауту — kill + `failed(TIMEOUT)`.
7. Тестируемость: трейт `CommandRunner` (spawn, wait, kill) с реализациями real/fake;
   integration-тесты используют небольшой fixture-exe, эмулирующий долгий вывод/ошибку/зависание.

## Альтернативы

- `cmd`/bat-обёртки — отвергнуто: нет контроля кодировок и кодов выхода.
- Polling процессов по таймеру — отвергнуто: событийная модель дешевле и точнее.
