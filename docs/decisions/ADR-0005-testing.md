# ADR-0005: Тестирование и E2E

Статус: принято.

## Решения

1. Rust: unit-тесты (`cargo test --lib`) для операций, хранилища, процессов и парсинга стратегий.
   Системные вызовы скрыты за трейтами, тесты не требуют прав администратора.
2. Frontend: Vitest для контракта `shared/api` — имена команд и форма аргументов.
   Компонентные тесты не вводятся: экраны проверяются в веб-демо и живом окне.
3. E2E-автоматизация не вводится. `tauri-driver` требует WebDriver и стабильного окна без
   кастомного titlebar, а сценарии всё равно упираются в драйвер WinDivert, UAC и живую сеть.
   Вместо этого — ручной чек-лист релиза (`docs/testing/TEST_PLAN.md`), он же покрывает
   установку, службу, трей и уведомления.
4. CI (GitHub Actions, `windows-latest`): `cargo fmt --check`, `cargo clippy -D warnings`,
   `cargo test`, `cargo check --lib`, `npm ci`, `typecheck`, ESLint, Vitest, `vite build`.
   Сборка установщика остаётся локальной.
5. Golden-тесты: парсер `.bat` стратегий проверяется на реальных файлах Flowseal.

## Ограничение

Автотесты не выполняют административных операций (службы, драйверы, System32) — только
через fakes и проверку валидации плана повышения прав без исполнения.
